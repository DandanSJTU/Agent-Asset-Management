# Evals 集设计说明

> Evals 是 AI 的单元测试：先定评测集与通过线，再让 AI 跑，人做最终确认。
> 团队约定：Evals 由产品 + 工程 + 算法共同定义，QA 约 0.5 人负责维护与执行，约占总工时 5%。

## 一、样本集结构（v3）
| 类别 | 覆盖内容 | 通过线关注点 |
|---|---|---|
| 低质内容 | 标题党、营销号高 CTR、猎奇、图文不符 | 是否被错误加权 / 是否被正确打压 |
| 冷启 | 新用户、新内容、新城市、低频内容 | 是否有基础曝光、explore 加权（1.5 倍）是否生效 |
| 行中场景 | 定位地 ≠ 常居地、行中周边城市 | 场景切换及时性、供给匹配度 |

## 二、通过线写法（必须数值化）
```
主判定：<指标> 在 <样本集> 上不低于 <阈值>
护栏：<另一指标> 变化幅度不超过 <阈值>
样本量：≥ N 条，覆盖 <平台/场景/人群> 组合
```
禁止："看起来还行""略有下降"。

## 三、误伤率基线（治理类策略必做）
- 定义：被策略影响但本不应被影响的样本占比。
- 分窗口给出：7d / 30d / 180d / 全生命周期。
- 用途：阈值标定的输入，也是上线后的回归对照。
- 当前缺口：曝光衰减打压的误伤率基线尚未产出（进行中，owner 许岸）。

## 四、回归策略
- 触发：任何策略 / 模型 / 配置变更。
- 范围：全量回归，不抽样；记录耗时与失败项。
- 失败：阻断进入灰度，输出失败样本清单与初步归因。
- 清理：失效样本定期清理，避免回归成本失控。

## 五、闭环
线上 Badcase → 沉淀为 Evals 样本 → 回归覆盖 → 防止复发。
当前痛点：Badcase 平台与 Evals 集尚未自动打通，靠人工搬运。
