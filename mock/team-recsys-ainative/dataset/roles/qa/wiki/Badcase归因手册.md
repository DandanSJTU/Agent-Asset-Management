# Badcase 归因手册

> 首页信息流评测主入口：Badcase 分析平台。
> 归因要求：落到具体环节与机制，证据链完整；归因不到环节的 case 不允许关闭。

## 一、四步法
1. **取 case**：uid、item、位置 index、场景（行前/行中/目的地）、平台（T/C）、时间点。
2. **分层**：用户分层（HASORDER / NOORDER_HASINTENT / NOORDER_NOINTENT）、新老用户、内容分层（BU、评级 level、通道）、位置、场景、平台。
3. **定位环节**：召回 → 粗排 → 精排 → 重排 → 退场。
4. **结论反哺**：结论 + 建议 + 沉淀为 Evals 样本。

## 二、各环节排查要点
| 环节 | 排查要点 |
|---|---|
| 召回 | 候选是否存在、来自哪条通道（CTP/ISA/IHC/SWI/STS/QR/NUC…）、城市配额是否失衡 |
| 粗排 | 是否被截断、粗排分与退场分融合后的排名 |
| 精排 | 分数与多目标权重，是否被时长/导流目标拉低 |
| 重排 | 城市打散（一城 ≤10）、时间 decay、标题/OCR simhash 打散、DPP 顺序变化 |
| 退场 | 是否过度降权（对照队列快照）或该降未降 |

## 三、高频 Badcase 类型
1. **视频评级误判**：内模糊时长 >1/4 仍评为优质；无封面图或封面不清晰进入分发。
2. **重复曝光**：退场未生效或队列截断数配置不当（城市级 top100 / 单品级 top5000）。
3. **同城扎堆**：城市打散未生效（一城 ≤10）。
4. **冷启无曝光**：新内容未进入 explore，或混排分时间衰减过重。
5. **标题雷同连排**：标题/OCR simhash 打散未覆盖（数据源 dw_mobdb.dw_tripshoot_main_ful）。

## 四、结论强度
- 强：证据链完整（候选 + 分数 + 位置）
- 中：缺 1 项
- 归因不成立：缺 ≥2 项，需补数据重查

## 五、注意事项
- 不从现象直接跳到结论（"模型不准"不是归因）。
- 不把单 case 当普遍问题，先判断是否可复现、是否成规模。
- 报告中的指标必须带口径（pv/uv、大报表/AB、底表）。
