# Agent 资产管理 · 无 Docker 安装指南

面向**没有 Docker、想直接源码跑起来**的场景。全程只需要 Node.js。

---

## 最快路径

```bash
tar xzf agent-asset-management-*.tar.gz
cd agent-asset-management
./install.sh
```

脚本会依次做：检查环境 → 装依赖 → 构建前端 → 引导填 LLM 配置 → 启动四个服务。
全程约 5~15 分钟，最后打印面板地址和登录 key。

---

## 前置要求

| 项目 | 要求 | 检查命令 |
|---|---|---|
| Node.js | **>= 22.16.0** | `node -v` |
| npm | 随 Node 安装 | `npm -v` |
| 编译工具链 | 可选，部分原生模块需要 | `python3 --version` `make --version` |
| LLM 凭据 | OpenAI 兼容格式（DeepSeek / 通义 / Kimi 等） | — |

> Node 版本不够会直接报错退出。用 nvm 装最快：`nvm install 22 && nvm use 22`

## 安装过程详解

`./install.sh` 分五步，任一步失败都会明确告诉你原因：

| 步骤 | 做什么 | 产物 |
|---|---|---|
| 1 | 检查 Node 版本、npm、编译工具链 | — |
| 2 | 对 4 个组件 + 前端各自 `npm ci` | 各目录 `node_modules/` |
| 3 | 构建面板前端（`tsc && vite build`） | `MemoryPanel/web/dist/` |
| 4 | 生成配置（交互式引导填 LLM） | `runtime/config/llm.env` |
| 5 | 启动服务 + 健康检查 | 四个进程 + `runtime/pids/` |

### 常用参数

```bash
./install.sh --skip-deps    # node_modules 已存在时跳过安装
./install.sh --force-deps   # 强制重装依赖
./install.sh --skip-start   # 只安装，先不启动
./install.sh --yes          # 非交互（配合环境变量，适合自动化部署）
```

非交互示例：

```bash
LLM_API_KEY=sk-xxxx \
LLM_BASE_URL=https://api.deepseek.com/v1 \
LLM_MODEL=deepseek-chat \
PROMPT_MODE=code \
./install.sh --yes
```

## 配置说明

**唯一配置文件：`runtime/config/llm.env`**。改完重新执行 `./start.sh` 即生效。

里面有两组 LLM，**互相独立，都要填**：

| 组 | 给谁用 | 用途 |
|---|---|---|
| `LLM_*` | MemoryCore（8420） | 记忆抽取 L1、场景归纳 L2、画像 L3、技能提炼 |
| `KNOWLEDGE_LLM_*` | MemoryKnowledge（8424） | Wiki / Code-Graph 文档抽取 |
| `PROXY_UPSTREAM_*` | MemoryProxy（8096） | coding agent 请求转发的上游模型 |

> 只填其中一组，另一处会报 `Failed to parse URL from REPLACE_ME/chat/completions`。
> 三组建**议填同一个**，最省事。

### promptMode 怎么选

| 值 | 适用 | 抽什么 |
|---|---|---|
| `code`（默认） | 代码工程、团队协作 | 技术方案、架构约束、决策记录、排障经验 |
| `chat` | 个人对话、教学、闲聊 | 用户偏好、背景信息、沟通约定 |

**配错的表现**：聊了很久面板里一条记忆都没有。换另一个值再试。

## 启动后：四个服务

| 服务 | 端口 | 用途 | 健康检查 |
|---|---|---|---|
| MemoryCore | 8420 | 记忆读写、鉴权、技能与知识数据面 | `/health` |
| MemoryKnowledge | 8424 | Wiki / Code-Graph | `/health`，Swagger 在 `/docs` |
| MemoryPanel | 8125 | **管理面板（日常主要用它）** | `/health` |
| MemoryProxy | 8096 | coding agent 的 LLM 代理 | `/health` |

### 日常命令

```bash
./start.sh            # 启动全部（会自动跳过已在运行的）
./start.sh core       # 只启某一个：core|knowledge|panel|proxy
./stop.sh             # 停止（SIGTERM → 等待 → SIGKILL）
./stop.sh --force     # 强杀，并清理残留占用端口的进程
./status.sh           # 状态快照
./status.sh --watch   # 每 5 秒刷新
```

### 首次登录

打开 <http://localhost:8125>，用安装结束时打印的 key 登录（也保存在
`runtime/config/.admin-key`）。

**建议的初始化顺序**（权限模型决定的，顺序错了会找不到入口）：

1. 用 admin key 登录 → 左上角团队切换器 →「**+ 新建团队**」（此入口仅 admin 可见）
2. 进入该团队 →「**成员管理**」→「添加成员」→ 方式选「**新建用户并加入团队**」
3. 弹窗会**一次性**显示新用户的 `user_key`（`sk-mem-...`），**当场复制保存**
4. 退出 admin，用业务用户 key 重新登录 → 在团队内建 Agent / Skill / Wiki / 记忆

> 面板上**没有独立的「用户管理」菜单**，建用户的入口挂在团队的成员管理里。

## 接入 Coding Agent

想让 Claude Code / CodeBuddy / Codex 之类的 agent 自动读写记忆，把它们的 API
指向本机 proxy：

```bash
# Claude Code
export ANTHROPIC_BASE_URL=http://127.0.0.1:8096/claude-code/default
export ANTHROPIC_AUTH_TOKEN='<业务用户的 sk-mem-...>'
claude
```

其他 agent（CodeBuddy / Codex / OpenCode / Hermes / OpenClaw）的配置方式见包内
`agents/` 目录下对应文档。

> 默认配置下 proxy 的 `auth` 和 `sessionInit` 都是关闭的（本机单用户体验最省事）。
> 想要「每次会话弹表单选团队/智能体/任务」的完整体验，把
> `runtime/config/proxy-config.yaml` 里这两项改成 `true` 后重启。

## 常见问题

**Q：`./start.sh` 报端口被占用**
先 `./status.sh` 看是不是已经在跑。确认是别的进程占用：

```bash
lsof -nP -iTCP:8125 -sTCP:LISTEN     # 换成被占的端口
kill <PID>
```

**Q：Node 版本够但 npm ci 报 node-gyp / 编译错误**

原生模块（MemoryKnowledge 的 `better-sqlite3`、MemoryProxy 的 `node-pty`）需要
编译工具链：

```bash
# macOS
xcode-select --install
# Ubuntu / Debian
sudo apt install -y python3 make g++
```

装完重跑 `./install.sh --force-deps`。
**只想要面板和记忆功能的话**，`node-pty` 编译失败可以直接忽略——proxy 是可选组件，
脚本已把它设为非阻断项。

**Q：填了 LLM key，但面板里就是没有记忆**

按顺序排查：

1. `runtime/config/llm.env` 里 `LLM_API_KEY` 是否还是 `REPLACE_ME`
2. `promptMode` 是否选错（闲聊场景用 `code` 模式基本抽不出东西，改 `chat`）
3. 核对 `LLM_BASE_URL` 是否带 `/v1` 后缀、key 是否有余额
4. 看日志 `runtime/logs/core.log` 里有没有 LLM 请求报错
5. 「Chat Memory」页确认 L0 原始对话已写入——有 L0 但没 L1，是抽取问题；
   L0 都没有，是对话没回流到 core

**Q：面板白屏**

前端构建产物缺失。检查 `MemoryPanel/web/dist` 是否为空，空的话重新构建：

```bash
cd MemoryPanel/web && npm run build && cd ../.. && ./stop.sh && ./start.sh
```

**Q：L1/L2 提炼很慢**

这是**设计如此**，不是卡住。L1 在会话静默 600 秒后触发，L2 在 L1 完成后延迟 90 秒、
且两次间隔不少于 900 秒。想调快改 `config-templates/tdai-gateway.yaml` 里的
`l1IdleTimeoutSeconds` / `l2DelayAfterL1Seconds`，然后 `./start.sh` 重新渲染生效。

**Q：vector 检索 / 语义搜索不准**

默认 `embedding.provider: none`，搜索走 SQLite FTS / BM25 **全文检索**，零配置可用。
要语义检索需自行配置 embedding provider 与密钥。

## 数据备份与迁移

所有业务数据都在 `runtime/data/`（SQLite 文件）。

```bash
./stop.sh
tar czf backup-$(date +%Y%m%d).tar.gz runtime/data runtime/config
./start.sh
```

换机器时把备份解压到新机器的 `runtime/` 下覆盖即可。
数据库文件路径在 `runtime/config/tdai-gateway.yaml` 的 `data.baseDir`（已自动渲染为绝对路径）。

```bash
./stop.sh
cd .. && rm -rf agent-asset-management
```
